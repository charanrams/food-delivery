## 2. Architecture
- Auth: `POST /api/v1/auth/login {identifier,password}` (email or phone). JWT access (memory) + rotating refresh (web: HttpOnly cookie `a3_rt`; mobile: `X-Client: mobile` → token in body, stored in secure storage). Role from server decides landing: ADMIN→/admin, DELIVERY_PARTNER→/delivery, CUSTOMER→/.
- Sign-up (customers only) = `POST /auth/register/otp {name,phone,email}` → emailed 6-digit code → `POST /auth/register {…,password,otp}`. Reset = `/auth/password/forgot {email}` (always 200, never reveals if the email exists) → `/auth/password/reset {email,otp,password}` (revokes all sessions). Codes: `AuthOtp` model, HMAC-hashed, one per email+purpose, 60 s resend cooldown, `OTP_MAX_ATTEMPTS`.
- Email: nodemailer Gmail SMTP (`backend/src/utils/mailer.ts`; `SMTP_*` + `APP_URL` in `backend/.env`). Empty `SMTP_USER` → mail printed to the log; `NODE_ENV=test` → `testOutbox` (tests read codes/passwords from it). Table-layout HTML templates with inline CID logo `backend/assets/logo.png` (192px; process cwd must be `backend/`).
- Delivery partners: admin-only `/admin/delivery-partners` — list/search, create (random password emailed with login link), PATCH details + status ACTIVE/SUSPENDED (suspend revokes sessions), `POST /:id/resend-credentials` (new password emailed), DELETE (blocked if any DeliveryAssignment → suspend instead). Profile has vehicleType/vehicleNumber. Partners are never self-registered.
- Catalog API done: public `/categories`, `/products`; admin CRUD `/admin/categories`, `/admin/products` (+availability, archive/restore), audit logs. Images: `/admin/uploads/sign` → signed direct Cloudinary upload (cloud `charan12`, creds in root `.env` only).
- Dev DB: no Mongo/Docker locally → mongodb-memory-server replica set **persisted to `backend/.data/mongo`** (wiredTiger, fixed port 27117; gitignored) so data survives `tsx watch` restarts; tests stay in-memory. Seeded once on an empty DB (`backend/src/scripts/seed-data.ts`; admin@/delivery@/customer@a3kitchen.in, pw `A3kitchen@123`). Wipe = stop server, delete `backend/.data`.
- Seed photos: Wikimedia Commons CC images in Cloudinary (`backend/src/scripts/photos.json`, credits in `backend/contracts/src/photo-credits.ts`, shown at web `/credits`).

## 7. Known Issues
- Cloudinary API secret and Gmail app password were pasted in chat — rotate both before production.
- Windows npm optional-deps bug: if vitest/tsx fail with missing `@rolldown/binding-*` / `@esbuild/win32-x64`, reinstall or add the binding.
- Mobile ↔ API: native apps send no Origin (CORS n/a). Dev CORS allows any localhost/LAN origin (`backend/src/config/cors.ts`). App base URL: Android emulator 10.0.2.2, web/iOS sim localhost, phone → `--dart-define=API_BASE_URL=http://<PC LAN IP>:4000/api/v1` + allow Node through Windows Firewall (Private).
- A stale Vite process on :5173 can serve index.html for `/api/*` (no proxy) → "We couldn’t load this" everywhere; restart `npm run dev:web`.

## 11. Do Not Repeat
- `google_fonts` in Flutter (v9 needs material_ui; v6 fails on Flutter 3.47) — fonts are bundled in `assets/fonts`.
- Cloudinary remote-fetch from Wikimedia (429) — download with User-Agent, then upload.
- Never log email subjects/bodies in non-dev — subjects contain one-time codes.
- Python file edits on Windows: pass `encoding='utf-8'` (default cp1252 crashes on non-ASCII after truncating the file).
